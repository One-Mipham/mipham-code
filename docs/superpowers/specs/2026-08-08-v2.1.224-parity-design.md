## 一、凭证遮蔽模块化 Pipeline

### 1.1 现状

`credential-masker.ts` (~200 行) 单文件实现：

- `matchCredentialFile()` — 路径匹配
- `maskContent()` — full 模式（全文件替换）+ extract 模式（正则替换）
- `maskOutput()` — stdout/stderr 清洗
- `filterEnv()` — 环境变量过滤
- `globToRegex()` — 内部 glob 转换

**缺失**：JWT decode + maskClaims、结构化 JSON 字段提取（extract + onExtractNoMatch）、AWS SigV4 检测与重签名。

### 1.2 目标架构

```
src/core/credential-masker/
├── index.ts              # re-export pipeline + 向后兼容 API
├── pipeline.ts           # MaskingPipeline — 策略链编排
├── matcher.ts            # matchPath + globToRegex（从现有文件提取）
├── env-filter.ts         # filterEnv（从现有文件提取）
├── output-scrub.ts       # maskOutput（从现有文件提取）
├── strategies/
│   ├── full.ts           # 全文件掩蔽策略
│   ├── extract.ts        # 增强 extract：结构化字段提取 + onExtractNoMatch
│   ├── jwt.ts            # 🆕 JWT decode + maskClaims
│   └── aws.ts            # 🆕 AWS 密钥对检测 + SigV4 重签名
└── types.ts              # 策略接口 + 扩展配置类型
```

### 1.3 策略接口

```typescript
interface MaskingStrategy {
  name: string
  /** 返回 true 表示此策略处理该规则 */
  canHandle(rule: CredentialFileRule): boolean
  /** 对内容执行遮蔽，返回遮蔽后的内容 */
  mask(content: string, rule: CredentialFileRule): string
}
```

### 1.4 Pipeline

```typescript
class MaskingPipeline {
  private strategies: MaskingStrategy[] = []

  register(strategy: MaskingStrategy): void
  maskContent(content: string, rule: CredentialFileRule): string
}
```

管道遍历策略列表，找到第一个 `canHandle()` 返回 true 的策略执行遮蔽。未匹配时走默认 full/extract 逻辑。

### 1.5 三项新增遮蔽策略

#### JWT 策略 (`strategies/jwt.ts`)

- 触发条件：rule 包含 `decode: "jwt"` + `maskClaims: string[]`
- 行为：Base64 解码 JWT payload（第二段），删除或替换 `maskClaims` 中指定的 claim 值
- 保留 JWT 结构（三段 `.` 分隔），header 和 signature 不变
- 示例：`maskClaims: ["sub", "email"]` → payload 中 `"sub":"xxx"` → `"sub":"[MASKED]"`
- 配置层校验：`decode: "jwt"` 需要 `network.tlsTerminate` 开启，且仅接受 user/managed 级别

#### 结构化 Extract 增强 (`strategies/extract.ts`)

- 增强现有 extract 模式，新增 `onExtractNoMatch` 字段：
  - `"mask"`（默认）：未匹配到任何 extract pattern 时遮蔽整个值
  - `"passthrough"`：未匹配时原样保留
- 新增 `extract[].field` 字段：从 JSON/INI/TOML 结构化值中按 key 提取
  - 例：`{"api_key": "sk-xxx", "endpoint": "https://..."}` → 只遮 `api_key`，保留 `endpoint`
- 向后兼容：不提供 `field` 时行为与现有 extract 一致（全文本正则匹配）

#### AWS SigV4 策略 (`strategies/aws.ts`)

- 触发条件：rule 包含 `awsPairs: true` + `sigv4: true`
- 行为：检测 `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` 配对
- 遮蔽：access key 保留前缀 `AKIA` + 4 字符，其余替换为 sentinel
- SigV4 重签名：沙箱出口处拦截 HTTP 请求，用原始密钥生成 SigV4 签名注入 Authorization header
- **注意**：重签名需要 `network.tlsTerminate` 开启 TLS 中间人能力，Phase 1 先实现检测+遮蔽，重签名留 Phase 2

### 1.6 配置扩展

```yaml
credential_masking:
  enabled: true
  files:
    # 现有格式向后兼容
    - path: '~/.aws/credentials'
      mode: extract
      extract:
        - pattern: "aws_secret_access_key\\s*=\\s*\\S+"
          replacement: 'aws_secret_access_key=__MIPHAM_CREDENTIAL_MASKED__'

    # 🆕 JWT 感知遮蔽
    - path: '~/.config/ci-token.json'
      type: jwt # 新 type 字段
      decode: jwt
      maskClaims: ['sub', 'email', 'iat']

    # 🆕 结构化提取（带 field）
    - path: '~/.config/service-account.json'
      mode: extract
      extract:
        - field: 'private_key' # 🆕 按 key 提取
          pattern: '.*'
          replacement: '[PRIVATE_KEY_MASKED]'
      onExtractNoMatch: mask # 🆕 未匹配行为

    # 🆕 AWS 密钥对
    - path: '~/.aws/credentials'
      type: aws
      awsPairs: true
      sigv4: true
```

## 二、跨会话消息系统

### 2.1 现状

- `AgentMessageBus` — 进程内单例，内存存储
- `SendMessage` 工具 — 调用 `bus.post()`，仅限同一进程

### 2.2 目标架构

### 2.3 Transport 接口

```typescript
interface SessionInfo {
  id: string
  name: string
  machine: string // hostname
  pid: number
  startedAt: string
  cwd?: string
  provider?: string
  model?: string
}

interface CrossSessionTransport {
  /** 发送消息到目标会话的 inbox */
  send(from: SessionInfo, toSessionId: string, msg: AgentMessage): Promise<boolean>

  /** 拉取当前会话的未读消息 */
  poll(sessionId: string): Promise<AgentMessage[]>

  /** 发现所有可访问的活跃会话 */
  listSessions(): Promise<SessionInfo[]>
}
```

### 2.4 FileInboxTransport

最简实现，文件系统作为传输层：

```
~/.mipham/
├── inbox/                     # 跨会话消息 inbox
│   ├── <session-id-1>/        # 会话 1 的收件箱
│   │   ├── 2026-08-08T12-00-00-msg001.json
│   │   └── 2026-08-08T12-05-00-msg002.json
│   └── <session-id-2>/        # 会话 2 的收件箱
│       └── ...
├── sessions/                  # 现有 — 会话持久化
│   └── .index.json
└── .active-sessions/          # 🆕 活跃会话注册
    └── <session-id>.json      # SessionInfo + 心跳时间戳
```

**发送流程**：

1. `SendMessage` 工具执行 → `MessageRouter.route()`
2. 如果 `to` 是本会话 agent → 走 `AgentMessageBus`（现有逻辑）
3. 如果 `to` 是其他会话 → `FileInboxTransport.send()`
4. 写入 `~/.mipham/inbox/<to-session-id>/<timestamp>-<msg-id>.json`
5. 写入前检查目录存在，不存在则创建
6. 返回 boolean 表示投递成功/失败

**接收流程**：

1. 会话启动时注册到 `~/.mipham/.active-sessions/<session-id>.json`
2. 心跳：每 30 秒更新 mtime
3. 引擎主循环每次 turn 前调用 `transport.poll(sessionId)`
4. 取回的消息通过现有 notification 通道展示给用户
5. 已读消息标记：删除 inbox 文件（或移动到 `.read/` 子目录）

### 2.6 安全设置

```yaml
# 🆕 新增配置项
crossSessionInbound: allow # allow | ask | deny
dialogExpiry: 300 # 秒，消息自动投递窗口
```

- `crossSessionInbound: "ask"` — 默认。跨会话消息到达时弹出审批，用户确认后投递
- `crossSessionInbound: "allow"` — 自动投递
- `crossSessionInbound: "deny"` — 拒绝所有跨会话消息
- `dialogExpiry` — 消息超过此时间未被拉取则过期（发件人收到投递超时通知）

**bypassed permissions 保护**：使用 bypassed permissions 运行的会话中，外来消息暂存，等待用户审批后放行。

### 2.7 与现有 SendMessage 的关系

现有 `SendMessage` 保持向后兼容：

- `to: "main"` → 发到父会话（现有逻辑，走 message-bus）
- `to: "<background-task-id>"` → 发到后台 agent（现有逻辑，走 message-bus）
- `to: "<session-id>"` → 🆕 跨会话发送（走 transport）

## 三、沙箱违规报告

### 3.1 现状

`bash.ts` 执行命令后只返回 stdout + exit code + stderr 错误。不检测沙箱违规场景。

### 3.2 改动

在 `bash.ts` 的 `execute()` 中，命令执行后增加违规检测步骤：

```typescript
// 🆕 沙箱违规检测
function detectViolations(stderr: string, command: string): string[] {
  const violations: string[] = []

  // 文件访问违规
  const accessMatch = stderr.match(
    /(?:Permission denied|EACCES|EPERM|Operation not permitted)\b.*?([/\w.-]+)/gi,
  )
  if (accessMatch) {
    violations.push(` File access denied: ${accessMatch.join(', ')}`)
  }

  // 网络访问违规
  const netMatch = stderr.match(
    /(?:Network is unreachable|Connection refused|ECONNREFUSED|ENETUNREACH)\b.*?([\w.:-]+)?/gi,
  )
  if (netMatch) {
    violations.push(` Network access denied: ${netMatch.join(', ')}`)
  }

  return violations
}
```

**集成点**：在 `bash.ts` 返回 result 之前：

```typescript
const violations = detectViolations(rawStderr, command)
let content = output.slice(0, 100_000) || '(no output)'
if (violations.length > 0) {
  content += '\n\n── Sandbox Violations ──\n' + violations.join('\n')
}
```

### 3.3 范围

仅 bash 工具。后续可扩展到其他 exec 工具（git, task 等）。
